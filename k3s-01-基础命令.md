## 一、创建第一个 Pod

先创建第一个 Pod，后续章节才有可操作的对象。不需要写 YAML，一条命令即可。

```bash
# 1. 创建 Pod
kubectl run whoami --image=traefik/whoami

# 2. 确认是否就绪（-w 持续监听，Ctrl+C 退出）
kubectl get pods -w

# 3. 查看它的输出
kubectl logs whoami

# 4. 将端口转发到本地（前台运行，不要关闭该终端）
kubectl port-forward pod/whoami 8080:80

# 5. 另开一个终端验证
curl localhost:8080

# 6. 使用完毕后删除
kubectl delete pod whoami
```

```text
$ curl localhost:8080
Hostname: whoami
IP: 127.0.0.1
RemoteAddr: 10.42.0.1:34567
GET / HTTP/1.1
Host: localhost:8080
User-Agent: curl/8.5.0
Accept: */*
```

**为什么用 `traefik/whoami`**：它会把收到的请求原样回显，可以看到 Host、User-Agent、来源 IP，比 nginx 的欢迎页提供的信息更多，镜像体积也更小。

**几点说明**：

- **裸 Pod**：`kubectl run` 创建的是没有 Deployment 托管的 Pod，删除后不会重建。它适用于临时验证；需要持久化和自动重启时，使用第五章的 YAML 方式
- **port-forward 是临时的**：前台运行，Ctrl+C 即断开，不是持久映射（与 `docker run -p` 的行为不同）
- **默认只监听 `127.0.0.1`**：如需局域网其他机器访问，需加 `--address 0.0.0.0`
- **目标可以替换**：Pod 名带随机后缀时，使用 `deploy/` 或 `svc/` 更便捷

```bash
kubectl port-forward pod/whoami 8080:80          # Pod
kubectl port-forward deploy/pairdrop 3000:3000   # Deployment（以后会用到）
kubectl port-forward svc/pairdrop 3000:3000      # Service（以后会用到）
```

## 二、查看资源

```bash
# 查看所有命名空间下的 Pod
kubectl get pods -A
kubectl get pods --all-namespaces

# 查看当前命名空间的 Pod
kubectl get pods

# 实时监听变化（Ctrl+C 退出）
kubectl get pods -w

# 查看详细信息（IP、节点、状态）
kubectl get pods -o wide

# 显示标签
kubectl get pods --show-labels

# 同时查看多种资源
kubectl get deploy,svc,pod

# 查看常见资源（不含 Secret / ConfigMap / Ingress / PVC）
kubectl get all

# Ingress 和 Traefik 中间件
kubectl get ingress
kubectl get ingress -A
kubectl get middleware

# 按标签筛选（kubectl run 创建的 Pod 自带 run=名字 标签）
kubectl get pods -l run=whoami

# 输出 JSON / YAML
kubectl get pod whoami -o yaml
kubectl get pod whoami -o json

# 只取某个字段
kubectl get pod whoami -o jsonpath='{.status.podIP}'

# 查看资源所属的 API 版本
kubectl api-resources | grep deployment
```

## 三、查看详情和日志

```bash
# 查看 Pod 详情，重点关注最下方的 Events
kubectl describe pod whoami

# 按标签查询，无需记 Pod 全名
kubectl describe pod -l run=whoami

# 其他资源同理
kubectl describe deploy <名字>
kubectl describe svc <名字>
kubectl describe ingress <名字>
kubectl describe node

# 查看容器日志
kubectl logs whoami
kubectl logs pod/whoami
kubectl logs -l run=whoami

# 实时跟踪日志
kubectl logs -f whoami

# 只看最近 100 行
kubectl logs --tail=100 whoami

# 查看上一个崩溃容器的日志
kubectl logs --previous whoami

# 多容器 Pod 指定容器
kubectl logs whoami -c whoami

# Pod 名带随机后缀时，按资源类型查询更方便（后续使用 Deployment 时会用到）
kubectl logs deploy/<名字>
```

## 四、进入容器

```bash
# 进入容器交互式 shell
kubectl exec -it deploy/frps -- sh
kubectl exec -it deploy/frps -- bash

# 指定 Pod 和容器
kubectl exec -it frps-xxx -c frps -- sh

# 执行单条命令（不需要 -it）
kubectl exec deploy/frps -- cat /etc/frp/frps.toml
kubectl exec deploy/frps -- ls -la /etc/frp/
kubectl exec deploy/frps -- env

# 指定 namespace
kubectl exec -it deploy/frps -n default -- sh
```

**语法要点**：

```text
kubectl exec [kubectl的flag] -- [容器里的命令]
                ↑                ↑
              -it -c          sh / bash / cat
              -- 是分隔符，前后都要有空格
```

## 五、创建和应用

```bash
# 用 YAML 创建/更新（最常用）
kubectl apply -f deployment.yaml
kubectl apply -f .                        # 当前目录所有 yaml
kubectl apply -f /opt/k3s/frps/              # 指定目录

# 仅预览生成内容，不实际执行
kubectl apply -f deployment.yaml --dry-run=client -o yaml

# 不手写 YAML，先生成模板再改
kubectl create deployment nginx --image=nginx --dry-run=client -o yaml > deploy.yaml
kubectl create secret generic frps-config --from-file=./frps.toml --dry-run=client -o yaml > secret.yaml
kubectl create ns dev
```

> 临时创建 Pod 的方法见第一章。

完整流程（Compose 迁移、Secret/Deployment/Service 三件套）见 [k3s-02-创建应用.md](k3s-02-创建应用.md)。

## 六、删除

```bash
# 按文件删除（删除文件里定义的所有资源）
kubectl delete -f deployment.yaml
kubectl delete -f /opt/k3s/frps/

# 按类型和名字删除
kubectl delete pod whoami
kubectl delete deploy frps
kubectl delete svc frps
kubectl delete secret frps-config

# 按标签删除
kubectl delete pods -l app=frps

# 强制删除卡住的 Pod
kubectl delete pod frps-xxx --force --grace-period=0

# 强制删除且不等结果
kubectl delete pod frps-xxx --force --grace-period=0 --wait=false

# ⚠️ 删除命名空间下所有工作负载（不含 Secret / ConfigMap / Ingress / PVC）
kubectl delete all --all -n default
```

## 七、Deployment 更新和回滚

```bash
# 查看滚动状态
kubectl rollout status deploy/frps

# 查看历史版本
kubectl rollout history deploy/frps

# 查看某个版本详情
kubectl rollout history deploy/frps --revision=2

# 重启（触发滚动更新，常用于 Secret/ConfigMap 改动后）
kubectl rollout restart deploy/frps

# 暂停 / 恢复滚动
kubectl rollout pause deploy/frps
kubectl rollout resume deploy/frps

# 回滚到上一版
kubectl rollout undo deploy/frps

# 回滚到指定版本
kubectl rollout undo deploy/frps --to-revision=2
```

## 十、命名空间

### namespace 在哪定义

**优先级从低到高：**

1. YAML 里显式写：

```yaml
metadata:
  name: frps-config
  namespace: default      # ← 这里
```

不写默认是 `default`。

2. kubectl 命令行指定：

```bash
kubectl apply -f secret.yaml -n dev
kubectl get pods -n kube-system
```

命令行 `-n` **覆盖** YAML 里的 namespace。

3. 切换默认 namespace：

```bash
kubectl config set-context --current --namespace=dev
```

### 常用命令

```bash
# 查看所有命名空间
kubectl get ns

# 创建命名空间
kubectl create ns dev

# 指定命名空间操作
kubectl get pods -n kube-system
kubectl get pods -n dev

# 查看所有命名空间的 Pod
kubectl get pods -A

# 查看当前默认 namespace
kubectl config view --minify | grep namespace

# 查看当前上下文
kubectl config current-context
kubectl config view
```

## 十五、Docker Compose 对照

以下按用途分组对照，左侧为 Docker / Compose 命令，右侧为等价的 kubectl 命令。

### 概念对照

部分概念名称相同但含义不同，另一些在 Docker 中没有对应物。

| Docker / Compose                 | K3s                                | 差别                                          |
| -------------------------------- | ---------------------------------- | --------------------------------------------- |
| 容器                             | Pod                                | Pod 可包含多个容器，共享网络与存储            |
| compose 中的一个 service         | Deployment                         | Deployment 管理副本数、滚动更新与自动重建     |
| `docker run -p 8080:80`          | Service（`port` + `targetPort`）   | 还需选择 `type`：集群内 / 节点端口 / 负载均衡 |
| `networks:`                      | 不需要                             | Service 名即 DNS，Pod 之间默认互通            |
| 挂数据目录 `-v ./data:/data`     | **PVC**                            | 存储与 Pod 解耦，Pod 重建后数据保留           |
| 挂配置文件 `-v ./conf:/etc/conf` | **ConfigMap**                      | 成为集群中的对象，不再依赖宿主机文件          |
| 挂 token / 证书                  | **Secret**                         | 同上，且可单独控制读取权限                    |
| `environment:`                   | `containers.env`                   | 相同                                          |
| `restart: always`                | 不需要                             | Deployment 自带自愈                           |
| `healthcheck`                    | `livenessProbe` / `readinessProbe` | 分为存活与就绪两种检查                        |
| `depends_on`                     | `readinessProbe`                   | K8s 不保证启动顺序，只能等待对方就绪          |
| 日志写文件 + `tail -f`           | stdout + `kubectl logs`            | Pod 会重建，写文件不可靠                      |
| compose 的项目名                 | namespace                          | 均可隔离，K8s 的隔离更彻底                    |
| Docker Hub                       | 同样是镜像仓库                     | 但 K3s 由 containerd 拉取，不走 Docker 配置   |

**最需要注意的是「挂载」** —— Docker 中一个 `-v` 可覆盖所有场景，K3s 中需按挂载内容区分：

```text
宿主机上那份内容是什么？
  ├─ 程序写入的数据（数据库文件、上传附件）        → PVC
  ├─ 只读配置（nginx.conf、不含敏感信息的 toml）   → ConfigMap
  └─ 敏感内容（token、密码、证书）                 → Secret
```

选择错误会导致问题：用 ConfigMap 存数据库数据 → 无法写入（ConfigMap 只读）；用 PVC 存配置 → 修改需进入容器操作，且没有版本记录。

具体到某个服务的迁移步骤，见 [k3s-02-创建应用.md](k3s-02-创建应用.md) 第一章。

### 查看

| 干什么           | Docker / Compose             | K3s                                  |
| ---------------- | ---------------------------- | ------------------------------------ |
| 运行中的容器/Pod | `docker ps`                  | `kubectl get pods`                   |
| 含已退出的       | `docker ps -a`               | `kubectl get pods -A`                |
| 容器详情         | `docker inspect xxx`         | `kubectl describe pod xxx`           |
| 实时日志         | `docker logs -f xxx`         | `kubectl logs -f deploy/xxx`         |
| 最近 100 行      | `docker logs --tail 100 xxx` | `kubectl logs --tail=100 deploy/xxx` |
| 崩溃前的日志     | —                            | `kubectl logs --previous deploy/xxx` |
| 资源占用         | `docker stats`               | `kubectl top pods`                   |
| 端口映射         | `docker port xxx`            | `kubectl get svc`                    |
| 镜像列表         | `docker images`              | `sudo k3s crictl images`             |

### 操作

| 干什么       | Docker / Compose                     | K3s                                                      |
| ------------ | ------------------------------------ | -------------------------------------------------------- |
| 起服务       | `docker compose up -d`               | `kubectl apply -f .`                                     |
| 改配置后生效 | `docker compose up -d`               | `kubectl apply -f .`，改 Secret 还要 `rollout restart`   |
| 重启         | `docker compose restart`             | `kubectl rollout restart deploy/xxx`                     |
| 停服务       | `docker compose stop`                | `kubectl scale deploy/xxx --replicas=0`                  |
| 停并删除     | `docker compose down`                | `kubectl delete -f .`                                    |
| 扩容         | `docker compose up -d --scale web=3` | `kubectl scale deploy/web --replicas=3`                  |
| 进容器       | `docker exec -it xxx sh`             | `kubectl exec -it deploy/xxx -- sh`                      |
| 拷文件       | `docker cp a xxx:/b`                 | `kubectl cp a pod:/b`                                    |
| 拉镜像       | `docker pull nginx`                  | `sudo k3s crictl pull nginx`                             |

### Docker 里没有的

| 干什么     | K3s                                           |
| ---------- | --------------------------------------------- |
| 看滚动状态 | `kubectl rollout status deploy/xxx`           |
| 回滚上一版 | `kubectl rollout undo deploy/xxx`             |
| 看历史版本 | `kubectl rollout history deploy/xxx`          |
| 按标签批量 | `kubectl get pods -l app=xxx`                 |
| 跨命名空间 | `kubectl get pods -A`                         |
| 看事件     | `kubectl get events --sort-by=.lastTimestamp` |

### 三个主要差异

- **停服务**：Docker 里 `stop` 就停了；K3s 里 Pod 会被 Deployment 立刻拉起来，要停只能把副本数改成 0
- **改配置**：Docker 里 `up -d` 即可全部生效；K3s 改 Secret/ConfigMap 不会自动生效，必须 `rollout restart`
- **容器名**：`docker exec` 用容器名就行；K3s 的 Pod 名带随机后缀，用 `deploy/名字` 省事

## 十六、易错点

### 1. exec 的 `--` 前后必须空格

```bash
# 错误
kubectl exec -it deploy/frps --sh
kubectl exec -it deploy/frps --bash

# 正确
kubectl exec -it deploy/frps -- sh
kubectl exec -it deploy/frps -- bash
```

`--` 是 kubectl 参数和容器命令的分隔符，不是命令的一部分。

### 2. `-f .` 是当前目录

```bash
# 要先 cd 到 YAML 所在目录
cd /opt/k3s/frps
kubectl apply -f .

# 或者写全路径
kubectl apply -f /opt/k3s/frps/
```

### 3. 改 Service 不用重启 Pod

```bash
kubectl apply -f service.yaml   # 立即生效
```

### 4. 改 Deployment template 会滚动重建

```bash
kubectl apply -f deployment.yaml
kubectl rollout status deploy/frps
```

### 5. 改 Secret/ConfigMap 后必须手动重启

```bash
kubectl apply -f secret.yaml
kubectl rollout restart deploy/frps   # 缺少这一步，Pod 仍在使用旧配置
```

哪些资源改了会自动生效、哪些必须重启（**Ingress / Middleware / Service 都不用**），完整对照见 [k3s-02-创建应用.md](k3s-02-创建应用.md) 的第八章。

### 6. 改 Deployment 的 selector 会报错

selector 不可变，要改只能删了重建。

### 7. K3s 的镜像存储和 Docker 不共享

Docker 拉过的镜像，K3s 看不到，要重新拉或导入：

```bash
# 重新拉
sudo k3s crictl pull snowdreamtech/frps

# 从 Docker 导入
docker save snowdreamtech/frps:latest -o /tmp/frps.tar
sudo k3s ctr -n k8s.io images import /tmp/frps.tar
```
